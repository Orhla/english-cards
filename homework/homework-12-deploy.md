# Домашнее задание 12 — Дополнительное: Деплой

Деплоим приложение в интернет. База — на Supabase, само приложение — на Vercel.

Это не задача с конкретным кодом, а последовательность шагов. На каждом шаге есть решение которое нужно принять самостоятельно.

---

## Шаг 1 — База данных на Supabase

**Что делать:**
1. Зарегистрируйся на [supabase.com](https://supabase.com) и создай новый проект
2. После создания проекта найди строку подключения: Settings → Database → Connection string → URI
3. Скопируй — это твой `DATABASE_URL` для прода

**Важно:** Supabase даёт два вида URL:
- `postgresql://...` — прямое подключение, одно соединение на запрос
- `postgresql://...pooler...` — через пул соединений (PgBouncer)

Next.js на Vercel — serverless: каждый запрос это новый процесс, который открывает соединение с БД и закрывает его. Прямое подключение при нагрузке исчерпает лимит соединений Postgres. Используй **pooler** (порт 6543).

Но есть нюанс: Prisma Migrate не работает через пулер. Для миграций нужно прямое соединение (порт 5432). Pogugли как в Prisma настроить два разных URL — один для рантайма, другой для миграций. Подсказка: `directUrl` в `schema.prisma`.

**Миграция:**
После того как оба URL прописаны в `.env` — примени миграции и seed:
```bash
npx prisma migrate deploy
npx prisma db seed
```

`migrate deploy` (не `migrate dev`) — для прода. Погугли разницу.

## Шаг 3 — Переменные окружения

Собери все переменные из `.env` которые нужны на проде. Посмотри на `src/lib/consts.ts` и `src/auth.ts` (или где настроен NextAuth) — там всё что нужно.

Список который точно нужен:
- `DATABASE_URL` — строка подключения к Supabase (pooler)
- `DIRECT_URL` — прямое подключение (для миграций, если настроила)
- `NEXTAUTH_URL` — полный URL задеплоенного приложения (узнаешь после деплоя)
- `NEXTAUTH_SECRET` — случайная строка, сгенерируй: `openssl rand -base64 32`
- `YANDEX_API_KEY`, `YANDEX_LLM_API_KEY`, `YANDEX_TRANSLATE_API_KEY`, `YANDEX_DICTIONARY_API_KEY`, `FOLDER_ID`

Запиши их — они понадобятся на шаге 4.

## Шаг 4 — Деплой на Vercel

1. Запушь ветку на GitHub
2. Зарегистрируйся на [vercel.com](https://vercel.com), подключи репозиторий
3. Vercel сам определит что это Next.js — настройки билда менять не нужно
4. Перед деплоем добавь все переменные окружения из шага 3 в настройках проекта (Settings → Environment Variables)
5. Задеплой

После первого деплоя Vercel выдаст URL вида `english-cards-xxx.vercel.app`. Обнови `NEXTAUTH_URL` этим значением и передеплой (или перезапусти без нового билда — в Vercel это называется Redeploy).

## Что может пойти не так

**Ошибка при билде — "Module not found"** — скорее всего импорт файла который существует только локально или опечатка в пути.

**Приложение запускается но БД не отвечает** — проверь `DATABASE_URL`: правильный ли хост, порт, пароль. Убедись что IP Vercel не заблокирован в настройках Supabase (по умолчанию Supabase принимает соединения отовсюду, но лучше проверить).

**Авторизация не работает** — скорее всего `NEXTAUTH_URL` не совпадает с реальным адресом, или `NEXTAUTH_SECRET` не задан.

**500 на любом экшне** — посмотри логи в Vercel (вкладка Logs в проекте). Там будет конкретная ошибка.

Кстати, Vercel показывает всё что пишется в stdout из serverless functions — то есть логи из Блока Б домашки 12 появятся прямо там. На бесплатном плане хранятся 1 час — для дебага в моменте хватает.
